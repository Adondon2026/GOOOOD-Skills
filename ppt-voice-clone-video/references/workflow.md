# 技术流程与交付规范

## 输入与清单

输入为参考录音、PPT 导出图片、DOCX/TXT 讲稿。图片按页号数值排序，避免 `1, 10, 11, ..., 2`。根据原稿页面分隔建立对应关系，不按文本长度猜分配。

页清单保存 `slide`、`title`、`image`、原稿路径或文本。合成后保存朗读文本、参考切片、模型及版本、种子、参数、片段 `start` 与 `duration`。记录原稿、参考和设置的摘要；恢复前核对输入一致性，不能只凭输出存在就跳过新输入。

原稿与朗读文本分开：`3.217` 可读作 `three point two one seven`，`WNOA` 可读作 `W N O A`，字幕仍显示原写法。小数按位读；缩写遵从领域习惯。保存映射，避免展开后错误回写原稿。

## 克隆、试音与批量

需要安装环境或定位部署问题时，先读 [chatterbox-turbo-deployment.md](chatterbox-turbo-deployment.md)。已有服务就复用，不重复执行部署路线。

官方来源：<https://github.com/resemble-ai/chatterbox>；Turbo 权重：<https://huggingface.co/ResembleAI/chatterbox-turbo>。新部署查询官方当前依赖，使用隔离环境；不把案例版本作为其他机器的通用安装方案。保留模型水印。

验证实际 GPU 运算与短段合成，不能只看 CUDA 是否可见。已有网页时通过 API 复用驻留模型。当前案例的 Gradio 接口为 `/generate`，输入顺序是文本、参考文件、起点、切片秒数、速度、种子、自动选段，返回 WAV、MP3、参考切片、状态：

```python
from gradio_client import Client, handle_file
client = Client('http://127.0.0.1:7861', verbose=False)
result = client.predict(text, handle_file(reference_path), 0, 15, 1.0, 42, True, api_name='/generate')
```

这是本案例接口，不是所有应用的固定接口。当前模型使用 `ChatterboxTurboTTS.from_local`、`prepare_conditionals(reference)`、`generate(text, temperature=0.75)`；重新部署以实际安装版为准。

参考可切为 24 kHz 单声道；自动响度/VAD 选段只是候选，检查音乐、混响及去伴奏残留。雄厚男声主要靠合适参考声线，不靠加混响或强降音高冒充克隆质量。

先生成短试音，匹配响度后让用户比较。本例批准原速 A。按自然句子/意群生成短段；本例约 32 个原稿词一段，实际朗读上限约 45 词。数字/缩写展开后再计算，不在字母序列、数值/单位或关键短语中截断。新模型长度限制按实测调整。

保存原生 WAV；按批准方案施加固定增益。本例目标 -24 LUFS，不是所有平台的标准。用 `pyloudnorm.Meter(sr).integrated_loudness(audio)` 测量，增益为 `10 ** ((target - measured) / 20)`。增益若会削波则限制并记录实际响度，不默默加压缩/限幅改变质感。

本例 WAV 是 PCM16、24 kHz 单声道，MP3 是 FFmpeg `libmp3lame` 192 kbps；片段间静音 0.22 秒、页间 0.5 秒。时间用 WAV 样本数确定，并检查 MP3 解码时长。

## 对齐与内容核验

案例对齐模型：<https://huggingface.co/facebook/wav2vec2-base-960h>；已知文本声学对齐方法参见 <https://github.com/m-bain/whisperX>。已有 Transformers 时可只部署英文 CTC 模型，不必额外下载完整的大型 ASR 栈。

逐个合成片段对齐，24 kHz 重采样到模型要求的 16 kHz，eval/inference 模式获得 CTC 概率。实现完整 CTC 路径时正确处理 blank、重复字符、状态跳转和回溯。数字展开、缩写和连字符的目标字符仍映射回原稿词。

词时间加片段偏移得到页内时间，再加页面偏移得到全局时间。结合识别文本检查数字、漏词、重复、句尾截断和异常跨度。专业词识别拼写不同不直接证明发音错误；强制对齐可能把错误读法硬贴到原稿，不能只看高置信度。

本例第 9 页把第二个小数误重复成第一个。将两个小数展开为英文词，仅重生成问题片段后恢复 `3.096 / 3.217`。修复后重算该页合并波形、响度、对齐和后续偏移，保留原错误证据。

## 短句、单行与核验

按句子、从句、停顿拆字幕，约 2–6 秒、6–12 词作为起点。尽量保持 `input and response channels`、`degrees per minute`、数值和缩写，不将冠词、介词、连词孤立在块尾。文字太长则增加字幕块，不能只删换行而忽略画面宽度。

每条文字默认单行，SRT 仍为“编号行 → 时间码行 → 文字行 → 空行”。对已批准的双行版本做单行转换时只连接文字行，不改断句、时间和文字。

首尾可加约 0.05 / 0.12 秒显示余量，以词间停顿为限。最短显示时长不能造成重叠。核验所有原稿词按序覆盖一次、数值不变、时间码合法、段间无重叠、不越页、不超音频；单行转换块数和时间码不变。

## 页表、合并与换页提示

辅助脚本读取 JSON 数组或 CSV，最少字段：

```json
[
  {"slide": 1, "start_seconds": 0, "end_seconds": 21.14},
  {"slide": 2, "start_seconds": 21.14, "end_seconds": 61.16}
]
```

完整页表还可含图片路径、标题、语音时长、页间停顿、图片时长、音频/字幕路径。每页区间包含它后面的页间停顿，末页不加停顿。用样本计数或足够精度的秒数累计，避免分别舍入每页时长引起漂移。

逐页字幕从各页零秒开始。合并音频为逐页波形和页间静音，全局字幕加上对应页开始时间。换页提示 SRT 每页一个完整区间，标记如 `PPT 01 / 16`；块边界就是该页图片边界。它不是原生剪映标记，不会自动导入图片或组装草稿。

用户手动操作：合并配音从 0 秒开始 → 导入提示 SRT → 开吸附、图片对齐块边缘 → 删除辅助块 → 导正式单行 SRT。不同版本导入第二份 SRT 可能复用字幕轨道，因此先对齐图片再导正式字幕；不保证多份字幕同时保留。调整图片时锁住音频，检查页号顺序。

提供时间码时明确 fps。30 fps 的 `00:00:21:04` 是 21 秒 4 帧，最后两位不是毫秒。舍入累计节点再计算区间，SRT 与帧网格允许半帧内差异。

## “机器回声”诊断

区分参考污染、合成伪影、后处理相位感、响度差和重叠播放。保留原生及处理 WAV，检查混响、复制混音、拉伸、错误重采样或削波。

公平 A/B 使用同一波形，一份原速、一份拉伸，匹配响度后比较。不同次随机合成不是严格对照。本例 0.95 的后期拉伸与用户感知的机器人感有关，用户选择原速 A；不能据此把所有机器感都归因于拉伸。44.1 kHz 立体声参考与 24 kHz 单声道产物只是带宽差异线索，不证明有回声。

先找到问题来源，再决定是否更换参考或参数，不优先用重降噪、增强高频或混响掩盖合成问题。
