# 证据优先写作

## 宗旨

**减轻读者不必要的理解负担，让读者能够快速、准确、流畅地理解所表达的内容。** 这是科研内容写作的首要原则，也是本技能组织文字、选择术语、安排图表和修改文稿的依据。

清晰表达需要作者承担组织材料和解释逻辑的工作。读者应能顺着文字理解研究对象、实验设计、证据与结论，无须反复回读、猜测指代、补齐推理或自行拼接散落的信息。简洁以保留必要信息为前提，不得为缩短篇幅省略设计依据、事实条件或结论边界。

默认采用直接陈述和连续论证。避免用问答式标题、连续设问、自问自答或“问题—答案”模板推进正文；用户明确要求访谈、FAQ或教学问答时除外。标题直接标明对象、方法、比较或结果，段落直接表达事实及其关系。

按理解所需的先后安排信息：先交代对象和条件，再说明操作及依据，随后呈现比较、结果和解释。术语在首次出现时就地定义；一个对象使用稳定的名称；比较写明共同条件与变化因素。图表应减少读者的查找、换算和跨段对应工作。

## 工作流程

1. 判断文本任务和目标读者，确定读者需要掌握的核心事实和必要背景。
2. 建立事实边界。区分材料直接支持的事实、合理解释和尚未证明的判断；不得补造引用、数据、结果或实验细节。
3. 优先采用“发生了什么 → 证据或原因 → 说明什么 → 边界或下一步”的组织方式。
4. 用具体动作和数字替代空泛评价。能写变化量、误差或条件时，不只写“更优”“鲁棒”或“有潜力”。
5. 修改现有文稿时采取局部手术式修改，保留技术含义、术语体系和原有正式程度；除非用户要求，不整篇重写。
6. 检查结论强度，避免把相关写成因果、把单一数据集结果写成普遍规律、把“没有证据”写成“不存在”。
7. 删除问答式组织、重复总结、结构播报、无证据评价和不必要的 AI 式套话。
8. 检查阅读路径：所需背景已在前文给出，逻辑衔接明确，指代清楚，术语一致；读者无需反复回读或自行拼接信息。

## 按任务选用规则

- 科研论文：区分 Abstract、Introduction、Methods、Results、Discussion 和 Conclusion 的职责；结果部分让数字和现象先行，讨论部分再解释意义与边界。
- 技术解释：按“定义 → 原理 → 例子 → 当前问题中的意义”组织。
- 专业邮件：按“写信目的 → 必要背景或更新 → 决定或请求 → 结束”组织。
- 普通沟通：按“事情 → 原因 → 下一步”组织，避免无谓学术化。
- 去 AI 味：删空泛评价词，把评价换成证据，删重复总结，打破过度工整句式，减少元叙述，并校准结论强度；不得靠错别字或不规范语法伪装自然。

## 详细规范

处理正式写作、长文修改或用户明确要求“去 AI 味”时，读取并遵循 [完整写作指南](references/writing-guide.md)。若用户给出材料或原稿，以材料实际内容和用户要求为最高事实边界。

## 交付检查

- 主旨清楚，必要背景在使用前给出。
- 采用直接陈述，避免问答式标题、连续设问和自问自答。
- 关键判断有证据，适合量化的内容给出数字和条件。
- 区分相关、因果、观察和解释。
- 每段承担一个主要任务，段落之间的逻辑关系明确。
- 指代清楚、术语一致，读者无需跨段查找或自行补齐推理。
- 删除无信息增量的结构播报、抽象词和重复结论。
- 语气符合场景和读者，结尾保留必要信息。

默认风格：简洁但不生硬，专业但不官腔，技术准确，证据优先，结论克制，句式自然，延续用户语言与术语。
